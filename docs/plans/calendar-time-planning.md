# 时间规划

本文只定计划，不改产品代码。对应 PR 只含本文。

会议句（「帮我定明早十点的周会」）继续走现有创建。时间规划只补「一句话里有好几件自己的事，要排进空档」。

守住已经定下的边界：

- 「现在」只来自日历账户的 IANA 时区。抽槽提示写上这一天和时区 id。相信模型给出的日期和钟点。确认卡片是把关的地方。
- 每次写入先出确认卡片。点确认之前不写 Google，也不插本地行。
- 信息不全时把空着的字段留在这张预填卡片上。不再多轮追问补槽。
- 不做双向同步。列表、侧栏、冲突、这次的忙闲，都当场读 primary `events.list`，读完不落库。
- 只做桌面 OAuth。
- 不新做工作时间。不把 `start_at` / `end_at` 写成带偏移的字符串。
- 不给抽槽加正则，不用关键词覆盖模型的日期、时长或标题。

## 1. 时间规划对用户是什么

用户用一句话列出几件自己的事，每件有主题和时长，也可以点名钟点，要排进某一天还没被占用的时间。例子：「帮我排一下明天：写报告2小时、健身1小时、回邮件30分钟」。

最小范围就是这件事，收窄为：

- 模型只听懂：哪一天、每件的标题、时长，以及用户有没有指定起止。
- 程序用一次当场的忙闲，按用户说的顺序，把「只有时长」的条目放进空档。
- 全部放在一张预填卡片上。用户改完、删完，点一次确认，才逐条写入。

「明天下午留两小时写报告」这种单条，不单独立项。无参与人的一条已经是创建：`extract_event` 允许参与人为空，`execute_calendar` 的 create 分支已经出一张确认卡片。它只差路由把它认成日程。模型若返回一条，仍走现有创建卡片。

代码里没有另一套规划对象，所以不另做这些：

- 优先级、为了腾地方去改已有日程、把一件事拆开、循环、路程、缓冲。
- 一周的最优解、上班时间、从上午才开始排。
- 新的意图或新的工具。
- 确认之后再提供「撤销整份规划」。写成之后，每一条都是普通日程，改期和撤销用现有卡片。

## 2. 路由现在怎么认，要改什么

意图和工具内的动作是两层。

意图在 `backend/app/agents/router.py` 的 `classify_intent` / `plan_tools`。模型按 `backend/app/core/prompts.py` 的 `ROUTER_SYSTEM` 填写 `needs_calendar`。路由没有正则兜底。`calendar.py` 里的 `calendar_hint` 不在这条路上。

日程契约现在是：创建、修改、撤销、查询，以及问某段时间有没有空。例子是开会、查日程、改期、取消、「明天下午有空吗」。「时间规划」「排一下明天」「留两小时写报告」都不在提示里。后一句可能被当成写作或闲聊。

进了日历工具之后，`workflow.py` 调用时不带 action。`calendar_tool.resolve_action` 用正则分流：有空 / 空闲 → `suggest`；有哪些 / 有什么安排 → `list`；取消 / 撤销 → `cancel`；改到 / 改成 → `update`；其余 → `create`。

「帮我排一下明天：写报告2小时、健身1小时、回邮件30分钟」对不上前四类，会落成 **create**。`extract_event` 只抽一条 `EventDraft`（主题、开始、结束、参与人）。三件事会被收成一条。模型没给结束时间时，`_finalize_prefill` 仍补成开始后 1 小时。这是单条创建的现有行为，规划条目不要沿用这个 1 小时。

改动：

- 意图保持 `calendar`。不加意图枚举，不加工具。
- `ROUTER_SYSTEM` 的日程契约写上：把几件自己的事排进某一天，也是 `needs_calendar`。补三条 few-shot：
  - 帮我排一下明天：写报告2小时、健身1小时、回邮件30分钟 → `needs_calendar=true`
  - 明天下午留两小时写报告 → `needs_calendar=true`
  - 什么是时间规划 → 全部 false
- `resolve_action` 不加「时间规划 / 排一下」正则。句子先被现有正则判成查询、改期、撤销或问空闲时，仍走原来的动作。
- 落在 create 时，抽槽 JSON 增加可选的 `items`。模型返回至少 2 条，才出规划卡片。0 条或 1 条仍是现有创建卡片。因此周会和「留两小时写报告」留在创建。
- 抽槽提示继续使用 `_extract_system_prompt` 里的「今天是 {日期}」和已连接时的 IANA id。多项时让模型输出 `items`：每条有 `title`，加上 `duration_minutes`，或者用户点名的 `start_at` / `end_at`。时间仍是无偏移墙钟。改期和撤销忽略 `items`。
- 模型若把三件事收成一条，用户看到一张创建卡片，自己改。不用关键词把它改判成规划。

## 3. 卡片

仍是一条 SSE `schedule_card`，存在 `messages.schedule_card`。不新开消息类型。

```json
{
  "mode": "plan",
  "phase": "draft",
  "action": "plan",
  "expires_at": "<draft_expires_at，30 分钟>",
  "items": [
    {"title": "写报告", "start_at": "2026-10-16T00:00:00", "end_at": "2026-10-16T02:00:00", "participants": []}
  ]
}
```

`start_at` / `end_at` 无偏移。参与人默认空数组。模型抽出了参与人就留在那一行，不要求填写。

`ScheduleCard.tsx` 在 `mode === "plan"` 时列出每一行。每一行可改标题和起止，可删行。删行只改卡片，不发请求。底部一个「确认创建」，一次提交留下的全部行。还有没填起止、或结束不晚于开始的行时，按钮不可用。缺了什么就空着，文案仍是请在卡片上补全，不追问。

点确认之前不写。没点确认又发下一句时，`chat.py` 已调用 `void_draft_schedule_cards`：`phase=draft` 且 `mode` 不是 `suggest` 的卡片改成 `cancelled`。规划的 mode 用 `plan`，这样忽略等于作废。过期仍走现有 `expires_at` 和 `isExpired`，过期也不能写。不加忽略按钮。

确认成功后，卡片进入已确认，列出写成的标题和时间。之后要改或撤销某一条，用现有的改期 / 撤销卡片。

## 4. 冲突，以及排不下时怎么办

忙闲和创建冲突同一套，只读一次：已连接走 `GoogleCalendarProvider._read_window` 的 primary `events.list`，并上本地行；未连接只有本地 overlap。不另调 freebusy，不把区间落库。规划直接调用 `free_gaps`，不走 `find_free_slots` 里的工作时间裁剪。对外加一个只读的忙闲区间函数，工具和确认接口都调它，不直接查表。

窗口是模型给出的那一天，墙钟从 00:00 到次日 00:00。模型给的是今天时，起点用 `calendar_now`，不往过去排。跨度超过 7 天就截到 7 天，和列表的窗口一样。

按说出的顺序放置：

- 模型给了起止：保持这段墙钟。它和忙闲或前面已放的条目重叠时，这一行标冲突，不挪走。可以附一段同样时长的空档（`free_gaps`，`limit=1`），用户点了才填进这一行。
- 只有时长：对「忙闲加上已放条目」调用 `free_gaps(..., limit=1)`。有空档就填上无偏移起止。没有空档就让起止为空，行保留，并标成未排下。

不重排、不缩短、不拆开、不移动 Google 上已有的日程。模型没给时长也没给钟点的行，起止为空，不补 1 小时。

`free_gaps` 把条目放在第一段空档的起点。明天全空时，第一件从 00:00 开始。这是现有函数的结果。用户在卡片上改钟点。

排不下的行仍留在这张卡片上，回复点出哪些标题没排下。用户删掉这些行，或自己填上起止之前，不能确认，也一条都不写。

读 Google 失败时，不把日历当成空的，不编空档。已点名的钟点留在行上，其余时间为空。文案用现有的「暂时没读到 Google 日历，确认时会再查；查不到就不会写入。」

确认走新的 `POST /api/calendar/plan`，正文是卡片上留下的条目：

1. 再读一次，窗口盖住这些条目里最早的开始和最晚的结束。
2. 任一条目和忙闲重叠，或条目彼此重叠：409，一条都不写，冲突回到卡片上。
3. 都空着：按顺序调用现有 `create_event`（已连接是先 Google、再本地行）。
4. 写到后面某一条失败：不删除已经写成的。应答写明哪些标题已经写入。卡片保持 `draft`，只留下没写成的行。

未连接时同一张卡片，冲突只看本地行，确认只写本地。

## 5. 切片

四刀，都进 `develop`。模型返回值由测试给定，不打真实模型。

### 1. 路由提示

只改 `backend/app/core/prompts.py`。

测试放在 `backend/tests/test_router.py`：`router_system()` 的文本含第 2 节的两句规划例子，以及「什么是时间规划」对应全部 false。不调模型。

实机：已连接时，那句三件事和「明天下午留两小时写报告」的意图是 calendar。「什么是时间规划」不进日历工具。这一刀还不会排出多项。

### 2. 抽出多项并预填，不写

改抽槽提示和 `execute_calendar` 的 create 分支。至少两条 `items` 时返回 `mode=plan` 的卡片。放置用一次忙闲读取加 `free_gaps`。这一刀不增加确认接口。

测试放在 `backend/tests/test_calendar_card.py`，`now` 固定为 `2026-10-15`，已连接时区为 `Asia/Singapore`：

- 模型返回明天三件，时长 120、60、30 分钟；10:00–12:00 已忙。卡片 `mode=plan`、`phase=draft`，三条都在，起止无偏移且不含 `+` 或 `Z`，按顺序落在空档里，没有一条占用 10:00–12:00。`calendar_events` 条数不变。
- 模型只返回一条：仍是 `mode=create`。
- 窗口里放不下的那条，起止为空，行还在。
- 点名的钟点与忙闲重叠：保留该钟点，并标冲突。
- 送进模型的提示含 `2026-10-15` 和 `Asia/Singapore`。没给时长也没给钟点的行，不补 1 小时。
- 读 Google 失败：不编空档，回复含「暂时没读到 Google 日历」，无写入。
- 下一句用户消息之后，这张 draft 卡的 `phase` 为 `cancelled`。

实机：明天在 Google 上放 10:00–12:00，再说那句三件事。应看到一张卡片，Google 上还没有这三件。不点确认，再发一句，卡片变为未确认，Google 仍没有。

### 3. 前端一张卡片

改 `frontend/src/components/ScheduleCard.tsx`。`mode=plan` 时多行可编辑、可删除，一个确认按钮。有空起止时按钮不可用。删除不发请求。

测试放在 `frontend/tests/scheduleCard.test.mjs`，沿用读源码的断言：规划分支有逐行标题和起止、删除不调用日历接口、确认只提交一次。浏览器上的点击放在第 4 刀的实机里。

### 4. 确认写入

新增 `POST /api/calendar/plan`。先整批查冲突，再逐条 `create_event`。

测试放在 `backend/tests/test_calendar_google.py`，使用现有的假 Google 客户端：

- 都空闲：插入次数等于条数，本地行数相同。
- 任一条重叠：409，插入 0 次。
- `events.list` 失败：502，插入 0 次。
- 第二条插入失败：第一条还在，应答点明未写入的标题。
- 未连接：只写本地，不调 Google。

实机（桌面，已连接，以账户时区为现在）：

1. 明天 Google 上已有 10:00–12:00。说「帮我排一下明天：写报告2小时、健身1小时、回邮件30分钟」。一张卡片、三行，不占用已有的两小时。此时 Google 没有这三件。
2. 改一行时间，删一行，点一次确认。Google 上只有留下的几件，墙钟与卡片一致。
3. 再说一句同样的话，不点确认，接着发「算了」。卡片变为未确认，没有新日程。
4. 把明天排满，使两小时放不下。放不下的那行时间为空，确认按钮不可用。Google 不变。
5. 「明天下午留两小时写报告」仍是一张单条创建卡。「帮我定明早十点的周会」仍是创建。「明天有空吗」仍是空闲建议。
