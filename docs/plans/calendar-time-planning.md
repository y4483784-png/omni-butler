# 时间规划

本文只定计划，不改产品代码。对应 PR 只含本文。

两件事：个人时间块走现有的创建确认卡；查日程和「怎么安排」走同一条 list 回复，先列出读到的日程，再给几句文字建议。不做多项填空档、不做规划卡片、不做 `POST /api/calendar/plan`、不用 `free_gaps` 排程，也不新加 `advise` 动作。

守住已有边界：「现在」只来自账户 IANA 时区；抽槽和建议提示写上今天和时区 id；相信模型，不加正则兜底；写入必须先出确认卡；不做双向同步；只做桌面 OAuth；`start_at` / `end_at` 保持无偏移墙钟；不新做工作时间。Google 读失败就说暂时读不到，不把没读到的时段说成空闲。

## 1. 个人时间块

「明天下午留两小时写报告」和「帮我定明早十点的周会」同一条路：`execute_calendar` 的 create 分支，一张现有确认卡。字段仍是标题、开始、结束；参与人可空。点确认之前不写 Google，也不插本地行。冲突、过期、下一句作废，都沿用创建。

路由只改 `backend/app/core/prompts.py` 的 `ROUTER_SYSTEM`。`router.py` 仍只出 `needs_calendar`，不加正则。few-shot：

- 明天下午留两小时写报告 → `needs_calendar=true`
- 帮我看看明天怎么安排 → `needs_calendar=true`
- 什么是时间规划 → 全部 false

抽槽仍是 `_extract_system_prompt`。补一句：用户说了时长，就把 `end_at` 写成开始之后的那段无偏移时间；个人事项的参与人留空，不要放进 `missing_fields`。模型没给结束时间时，现有 `_finalize_prefill` 仍补 1 小时，用户在卡片上改。不新增时长字段，不用正则解析「两小时」。

## 2. 查日程和怎么安排是同一条回复

「查本周日程」「明天有什么安排」「帮我看看明天怎么安排」都走现有 list。回复永远两段：先是日程列表，然后几句建议。建议看密度、缓冲、整段空闲是否适合专注、这一天是否太满该挪走某件。不要把每个空档都填上，也不要创建日程。没有卡片，没有写入。

「明天有空吗」仍走 suggest，不附这几句建议。

用户接着说「那明天下午留两小时写报告」时，这是新的一句话，走第 1 节的确认卡。建议文字不记成待补的槽。

列表仍用 `provider.list_events`：已连接是 primary `events.list`（可并上本地行），读完不落库；未连接只有本地行。行文沿用 `_list_line`。

窗口由模型给出，代码不解析「明天」「本周」：

- 模型给出 `day`（`YYYY-MM-DD`）：只列那一天，墙钟 00:00 到次日 00:00。点名了某一天的查询和「怎么安排」用这个窗口。
- `day` 为空：沿用 `_list_text` 现在的窗口，从账户「现在」当天 0 点起 7 天。本周、这几天、没点名某一天，都用它。

提示写上今天和时区，并说明：点名了某一天就填 `day`，说本周或没点名就留空。模型没给 `day` 时不改用正则去猜。

`execute_calendar` 的 list 把整段文字放进 `direct_answer`。`workflow.py` 的 `reflect_node` 见到它就停止，`answer_node` 不再调用 `complete_text`。建议因此要在 list 分支里写好，再放进同一个 `direct_answer`：程序先拼列表，再单独调用一次 `complete_text`，把几句话接在列表后面。不拆掉这个短路，也不把建议交给通用回答提示。`schedule_card` 保持 `None`。

建议提示里放今天、时区，以及刚列出的标题和墙钟，并写明只评论密度、缓冲、整段空闲和是否过载，不要逐段填空，不要输出卡片。

读失败时不调用建议模型。`calendar_now` 失败，或 `list_notice` 为「暂时读不到 Google 日历，以下只是这里保存的日程。」「这次没有列完。」时，回复就用现有这句（读失败时 list 已附带的本地行可以留着），不追加建议，也不把没读全的时段说成空闲。未连接没有这句，建议只根据本地行。建议模型自己失败时，列表照常返回，并接上「暂时给不出建议」，不在代码里编建议。

## 3. 怎么进 list

不加 `advise`，抽槽 JSON 也不加 `kind`。`resolve_action` 仍先处理 suggest / list / cancel / update。「明天有空吗」因「有空」进 suggest。「明天有什么安排」因「有什么安排」进 list。

「帮我看看明天怎么安排」和「查本周日程」对不上 `_LIST`，现在会落到 create。路由只出 `needs_calendar`，`workflow.py` 调用日历时 `tool_args` 为空，传不进动作。不加「怎么安排 / 本周」正则。

落到 create 时，抽槽多问一个现有动作名：`list` 或 `create`。模型返回 `list`（查询或怎么安排）就进入第 2 节，并带上 `day`。返回 `create` 或缺这个字段时，仍是创建卡。改期和撤销的提示不问这个字段。已经由正则进了 list 的句子，不再抽创建字段，只问 `day`，然后同样列表加建议。

## 4. 切片

三刀，都进 `develop`。模型返回值由测试给定。

### 1. 路由提示

只改 `ROUTER_SYSTEM`。

测试在 `backend/tests/test_router.py`：`router_system()` 含第 1 节三条 few-shot。不调模型。

实机：两句规划用语的意图是 calendar；「什么是时间规划」不进日历工具。这一刀里「怎么安排」仍会落到创建。

### 2. 个人时间块仍是创建卡

只改创建抽槽提示。

测试在 `backend/tests/test_calendar_card.py`。`now` 固定 `2026-10-15`，已连接时区 `Asia/Singapore`：

- 提示含 `2026-10-15`、`Asia/Singapore`，以及「说了时长就写 end_at」「参与人可空」。
- 模型返回标题「写报告」、`2026-10-16T15:00:00`、`2026-10-16T17:00:00`、参与人 `[]`：卡片就是这些值，`mode=create`，`phase=draft`，起止不含 `+` 或 `Z`。不写库。
- 模型没给 `end_at`：结束仍是开始后 1 小时。
- 该时段已有日程：卡片仍带现有的 `conflicts`，不写入。

实机：说「明天下午留两小时写报告」。一张创建卡，参与人为空，Google 上还没有。点确认之后才有一条，墙钟与卡片一致。不点确认再发一句，卡片变为未确认。

### 3. list 回复带上建议

扩展 list 分支。正则已是 list 的，以及抽槽把动作标成 `list` 的，都返回列表加建议。无卡片，无写入。

测试在 `backend/tests/test_calendar_card.py`，读取用现有的假 Google / 本地行。`now` 固定 `2026-10-15`：

- 模型给出 `day=2026-10-16`，当天有「周会」：`list_events` 的窗口是这一天的 00:00 到次日 00:00。回复先含「周会」和它的墙钟，再接建议。`schedule_card` 为 `None`。`calendar_events` 条数不变。
- `day` 为空：窗口是 `2026-10-15` 0 点起的 7 天。回复仍先列表、后建议。
- 送进 `complete_text` 的提示含列表，并写明不要逐段填空，要看密度、缓冲、整段空闲、是否过载。提示含今天和 `Asia/Singapore`。
- `events.list` 失败：回复含「暂时读不到 Google 日历」，不调用建议模型。
- 建议模型抛错：列表仍在，并含「暂时给不出建议」。
- 未连接：回复是该窗口的本地行加建议，不调 Google。
- 「帮我看看明天怎么安排」在抽槽标成 `list` 时走上面的回复，不出创建卡。「明天下午留两小时写报告」抽槽标成 `create` 时仍是创建卡。
- 「明天有空吗」仍是 suggest，不调用这次的建议模型。

实机（桌面，已连接）：

1. 明天 Google 上已有一场会。说「帮我看看明天怎么安排」，再说「明天有什么安排」。两句都先列出这场会，再有几句建议。没有卡片，Google 没有新日程。
2. 说「查本周日程」。列出从今天起 7 天里读到的日程，后面同样有建议。
3. 建议里出现「会太密 / 留出空档 / 太满可以挪」这类话即可；不要变成把每个空档都排上事情。
4. 断开或让读取失败：只看到暂时读不到，没有编出来的空闲上午，也没有建议段。
5. 接着说「明天下午留两小时写报告」：一张创建卡。确认前 Google 不变；确认后只有这一条新日程。
6. 「明天有空吗」仍是空闲建议卡，没有上面那种顾问段落。
