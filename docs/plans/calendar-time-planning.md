# 时间规划

本文只定计划，不改产品代码。对应 PR 只含本文。

两件事：个人时间块走现有的创建确认卡；「帮我看看明天怎么安排」只读当天日程，再用文字给几条建议。不做多项填空档、不做规划卡片、不做 `POST /api/calendar/plan`、不用 `free_gaps` 排程。

守住已有边界：「现在」只来自账户 IANA 时区；抽槽和顾问提示写上今天和时区 id；相信模型，不加正则兜底；写入必须先出确认卡；不做双向同步；只做桌面 OAuth；`start_at` / `end_at` 保持无偏移墙钟；不新做工作时间。Google 读失败就说暂时读不到，不把没读到的时段说成空闲。

## 1. 个人时间块

「明天下午留两小时写报告」和「帮我定明早十点的周会」同一条路：`execute_calendar` 的 create 分支，一张现有确认卡。字段仍是标题、开始、结束；参与人可空。点确认之前不写 Google，也不插本地行。冲突、过期、下一句作废，都沿用创建。

路由只改 `backend/app/core/prompts.py` 的 `ROUTER_SYSTEM`。`router.py` 仍只出 `needs_calendar`，不加正则。few-shot：

- 明天下午留两小时写报告 → `needs_calendar=true`
- 帮我看看明天怎么安排 → `needs_calendar=true`
- 什么是时间规划 → 全部 false

抽槽仍是 `_extract_system_prompt`。补一句：用户说了时长，就把 `end_at` 写成开始之后的那段无偏移时间；个人事项的参与人留空，不要放进 `missing_fields`。模型没给结束时间时，现有 `_finalize_prefill` 仍补 1 小时，用户在卡片上改。不新增时长字段，不用正则解析「两小时」。

## 2. 规划建议

只读，不出卡片。先列出那一天已经有的日程，再给几句文字建议。建议要帮用户把这一天排得更好，例如：会太密，中间留缓冲；有一整段空闲，适合放需要专注的事；这一天太满，哪一件可以挪走。不要把每个空档都填上，也不要替用户创建日程。

用户接着说「那明天下午留两小时写报告」时，这是新的一句话，走第 1 节的确认卡。建议文字不记成待补的槽。

当天的日程用 `provider.list_events`：已连接是 primary `events.list`（可并上本地行），读完不落库；未连接只有本地行。窗口是模型给出的那一天，墙钟 00:00 到次日 00:00。不复用 `_list_text` 的「从现在起 7 天」。哪一天由模型根据提示里的今天和时区决定。模型没给日期时，回复说没有得到要看的那一天，不扫描 7 天，也不用正则猜「明天」。

建议是单独一次 `complete_text`。提示里放今天、时区，以及上面列出的标题和墙钟，并写明：只评论密度、缓冲、整段空闲和是否过载；不要逐段填空；不要输出卡片。回复先是日程列表（程序按读到的行拼，沿用 `_list_line`），后面接模型的几句话。`schedule_card` 为 `None`。

读失败或 `list_notice` 为「暂时读不到 Google 日历，以下只是这里保存的日程。」「这次没有列完。」时，只返回这句说明，不调用建议模型。未连接时没有这句，建议只根据本地行。建议模型自己失败时，列表照常返回，并写「暂时给不出建议」，不在代码里编建议。

## 3. 建议用新动作，不复用 list

用日历工具里的新动作 `advise`。`resolve_action` 仍先处理现有的 list / suggest / cancel / update。「明天有空吗」仍是 suggest，「查本周日程」仍是 list。

不把建议塞进 list，有三处代码原因：

- `execute_calendar` 的 list 分支把 `_list_text` 放进 `direct_answer`。`workflow.py` 的 `reflect_node` 见到 `direct_answer` 就停止，`answer_node` 不再调用 `complete_text`。列表文本就是全部回复，后面没有第二段模型评论。
- `_list_text` 固定从账户「现在」的当天 0 点起列 7 天，不是用户点名的那一天，也没有顾问提示。改它会让「查本周日程」变成建议。
- 「帮我看看明天怎么安排」对不上 `_LIST`（有哪些 / 有什么安排 / 查日程等）。现在会落到 create。要让它变成 list，就得加正则，这和「相信模型」冲突。路由也只出 `needs_calendar`，不会把动作传进工具（`workflow.py` 调用日历时 `tool_args` 为空）。

因此：正则落到 create 之后，看抽槽 JSON 的 `kind`。`advise` 且带上 `day`（`YYYY-MM-DD`）就走第 2 节，不使用抽出的那条日程。缺 `kind` 或 `kind` 为 `create` 时仍是创建卡，旧的模型输出不用改。改期和撤销的提示不要求 `kind`。不加「怎么安排」正则。

## 4. 切片

三刀，都进 `develop`。模型返回值由测试给定。

### 1. 路由提示

只改 `ROUTER_SYSTEM`。

测试在 `backend/tests/test_router.py`：`router_system()` 含第 1 节三条 few-shot。不调模型。

实机：两句规划用语的意图是 calendar；「什么是时间规划」不进日历工具。这一刀里「怎么安排」仍会落到创建。

### 2. 个人时间块仍是创建卡

只改创建抽槽提示。

测试在 `backend/tests/test_calendar_card.py`。`now` 固定 `2026-10-15`，已连接时区 `Asia/Singapore`：

- 提示含 `2026-10-15`、`Asia/Singapore`，以及「说了时长就写 end_at」「参与人可空」。
- 模型返回标题「写报告」、`2026-10-16T15:00:00`、`2026-10-16T17:00:00`、参与人 `[]`：卡片就是这些值，`mode=create`，`phase=draft`，起止不含 `+` 或 `Z`。不写库。
- 模型没给 `end_at`：结束仍是开始后 1 小时。
- 该时段已有日程：卡片仍带现有的 `conflicts`，不写入。

实机：说「明天下午留两小时写报告」。一张创建卡，参与人为空，Google 上还没有。点确认之后才有一条，墙钟与卡片一致。不点确认再发一句，卡片变为未确认。

### 3. 只读建议

create 分支识别 `kind=advise`。读模型给出的那一天，返回列表加建议，无卡片，无写入。

测试在 `backend/tests/test_calendar_card.py`，忙闲用现有的假 Google / 本地行：

- `kind=advise`、`day=2026-10-16`，当天有「周会」：回复含「周会」和它的墙钟；`schedule_card` 为 `None`；`calendar_events` 条数不变。
- 送进 `complete_text` 的提示含当天列表，并写明不要逐段填空，要看密度、缓冲、整段空闲、是否过载。
- `events.list` 失败：回复含「暂时读不到 Google 日历」，不调用建议模型。
- 未连接：回复是本地行加建议，不调 Google。
- 没有 `kind` 的周会抽槽仍是创建卡。
- 下一句抽槽为创建时，出确认卡，仍不在出卡时写入。

实机（桌面，已连接）：

1. 明天 Google 上已有一场会。说「帮我看看明天怎么安排」。回复先列出这场会，再有几句建议。没有卡片，Google 没有新日程。
2. 建议里出现「会太密 / 留出空档 / 太满可以挪」这类话即可；不要变成把每个空档都排上事情。
3. 断开或让读取失败：只看到暂时读不到，没有编出来的空闲上午。
4. 接着说「明天下午留两小时写报告」：一张创建卡。确认前 Google 不变；确认后只有这一条新日程。
5. 「明天有空吗」仍是空闲建议卡；「查本周日程」仍是 7 天列表，没有顾问段落。
