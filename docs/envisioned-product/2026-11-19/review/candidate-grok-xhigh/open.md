# Open points

Settled decisions are not listed here. Flash plus independent Search and Fetch, the conversation and background split, no resident stop control, no earth button, keeping Zhipu embeddings, rerank, and ingest OCR, server-side tasks, a progress watchdog, device hashes, and no auto-allow stay closed. R2 and R3 are not questions. Device enrollment is the signed-in user, the token is shown once, and the web settings list revokes by id.

## Mail transport

The operator chooses the mailbox transport and where its credentials live. `mail` lands without that choice: an empty setting does not consume the claim and does not say the mail was sent. A live "sent" against a real mailbox waits for the choice. The missing lookup key, when a transport accepts and the response is lost before any provider id is stored, stays a gap. It is not closed by picking a vendor in this design.

This blocks a live send. It does not block the mail seam or any other unit.

## Browser dependency

The errand unit does not add a browser library. The existing compose service stays. A browser dependency is allowed only after all of the following are checked and the operator says yes:

1. The candidate runs a tool round with the chat role's model, `deepseek-flash`, using the tool message shape in the opened Thinking Mode guide.
2. A write is blocked before it runs, and the blocked call returns its parameters to a `ScheduleConfirmClaim`. The model does not receive a success result for that write.
3. The result is structured evidence. Payment and login fields are absent, matching the sealed names already dropped by `_public`.
4. A connector remains the path when the merchant has `place_url` and `lookup_url`. The browser is not a second conversation layer and does not replace the job.

Any failed check keeps the connector and the current compose service. Poke and Vesta pages are product examples. They are not evidence of Stagehand, of a success rate, or of a library already in this repository. Playwright in the current compose service is the existing channel. It is not an autonomous agent.

This blocks adding a dependency. It does not block `errand`.

## Silence threshold

No duration was confirmed for how long a job may go without progress before the first notice. `watch` does not use one. An unchanged `last_progress_at` produces one notice and does not stop the job. The existing 60-second beat stays because it is already scheduled. A later number would only delay the notice. It does not change the stop rule and it does not block `watch`.
