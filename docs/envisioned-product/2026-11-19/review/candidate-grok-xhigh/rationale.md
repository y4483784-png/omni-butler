The unit boundaries follow the code that has to change together: the image wire, the job row, the sweep, the tool loop, the search client, the three receipts, the device table, reconnect, and the local card. They are not the fourteen knife names and they are not a split copied from another plan.

Adopting the historical Gemini unit split was rejected because that mapping was not opened and the boundaries above were reached from the current functions.

Redoing the fourteen merged knives was rejected because those knives are the release behavior this design starts from.

One serial queue for every new sentence was rejected because `begin_turn` already stops the previous open turn and the confirmed architecture keeps the job running.

Copying OpenCode's default steer, Hermes's default interrupt, or DS-Bot's model-call cancel was rejected because a new sentence is a classification, not an interrupt.

Sending search through the Pro Responses `web_search` path was rejected because that is PR 93 and the opened pricing page limits that built-in tool to Pro.

A keyword table for supplement, redirect, new task, and cancel was rejected because `Role.ROUTER` already returns JSON and the decision forbids routing every message by phrase.

A new database product or a new service was rejected because SQLAlchemy, Alembic, and the existing Celery app already persist rows and run tasks.

Inventing a temperature, an output-token limit, a silence duration, a retry count, or an unread API field was rejected because the opened guides and `config.py` already name the values this design is allowed to use.

Copying allow-always, remembered rules, or unattended allow was rejected because the confirm claim is the gate.

Installing Browser Use in this design was rejected because the dependency is still a verification gate.

Choosing Gmail or SMTP inside the mail unit was rejected because the operator owns that choice and the seam can land without it.

Treating `uuid4()` as mail acceptance was rejected because `commit_send` already does that and the target requires a provider id.

Treating the Google `requestId` as the event id was rejected because insert already stores them as different values and `_written_claim` matches the armed id.

Marking an errand placed when `outcome` is `placed` and the echo is empty was rejected because that is the current `interpret` branch and the target requires the armed id and the merchant order id.

Keeping one shared desktop token was rejected because `recognize_package` accepts any package that presents it.

Using `finish` to move a waiting job back to `running` was rejected because `finish` on `waiting_person` keeps the status and `_validate_moves` rejects a target of `running`.

Closing the job when the last subscriber leaves was rejected because disconnect must not cancel.

Copying Hermes's blank-space padding of empty reasoning was rejected because the opened Thinking Mode guide does not describe it.

Changing the embedding or vision code defaults was rejected because the example file is the mismatch and the code defaults stay.

Treating R2, R3, or the follow-up root phase as the architecture target was rejected because R2 is a product choice, R3 is existing memory behavior, and the button phase is a display fix inside `resume`.

Using the in-process watchdog ledger as restart recovery was rejected because it lives on the worker process and is lost on restart.
