# 决策记录

这份记录只记计划审阅之后补上的决定。它不是初稿。十四刀的顺序没有改。

## 2026-11-10 操作者审阅后批准的细化

操作者看过 `envisioned-product-plan.md` 之后，批准把下面五条写进现有 PR #78。初稿只列了四种任务状态，并把确认卡的去重写成同一用户、同一代次、同一动作、同一参数指纹。那两处从这一天起不再有效。

### 已批准

1. `TaskRun` 有五种状态。`running`、`waiting_person`、`waiting_resource`、`completed`、`stopped`。正常做完是 `completed`。`stopped` 只表示人主动停掉，或看门狗安全停掉。不要把正常做完标成 `stopped`。不要用附加 reason 字段代替第五种状态。上一句已经讲完再开下一句时，旧一代是 `completed`。做到一半又发一句，或点了停止，旧一代是 `stopped`。看门狗安全停掉也是 `stopped`。看门狗不要把 `completed` 当成卡住、失败或取消。第二句话到来之后，第一句不得再停在 `running`。终态按上面的规则选。`ev-task` 就按这个做。`ev-events`、`ev-watch`、`ev-memory` 读状态时必须能分开「做完了」和「被停掉」。

2. 同一件待办写按同一用户、同一动作、同一参数指纹只留一条和一张确认卡。聊天、日历提醒、新邮件、脉搏都共用这一条。`generation` 只表示这一轮有没有被停掉。它不是「是不是同一件写」的键。总清单落在 `ev-gate`。`ev-task` 不得把同一件写绑死在代次上，以致以后只能推翻重来才能加这张清单。

3. 不要相信客户端在 `ChatRequest` 上自行填的 web 或 desktop。服务器根据登录和安装包认出表面。网页即使把自己报成 `desktop`，本机工具也必须被拒绝。测试覆盖这种撒谎。做到 `ev-webblock` 和 `ev-desktop` 时按这个做。

4. `ev-desktop` 的 Compose 服务名单对照 `ev-errands` 完成后的名单，不对照写计划时的 `release`。已有服务的职责不变。允许保留 `ev-errands` 新增的那一个专用浏览器服务。

5. `ev-stop` 就规定，这一代已经 `stopped` 时不要写长期记忆，也不要为写记忆再调模型。`ev-memory` 只加账本。不要把「停止后还能不能写记忆」留到 `ev-memory`，也不要留成中间状态。现状是 `chat.py` 第 681 到 687 行在停止后仍可能写记忆。这条写进 `ev-stop` 的范围和验收。

### 仍待定

这三条不卡住 `ev-task`。建议不是定案。

1. 邮件怎么收进来还没选定。推送、定时查看或其他方式都还没定。做到 `ev-mail` 再定。本计划不建议现在预选其中一种。已经定下的约束是，新邮件单独收下，不占用会前搜索邮件的只读用途。打开写信链接不等于已经发出。

2. 办事用哪种浏览器库还没选定。只定了单独的 Compose 服务和确认。做到 `ev-errands` 再定。放在单独服务里，不要塞进现在的主 api 服务。登录和付款仍要用户确认。

3. 桌面怎么打包还没选定。常见做法里提到过 Electron 和 Tauri，没有选定。建议用 Electron，因为现有 Vite 前端已经能嵌进去，PR #77 也更靠近这个选择。做到 `ev-desktop` 时可以按这个建议做，除非当时发现明显不合适。

### 怎么落地

仍然一次只做一刀。每一刀代码做完后，还要做 pstack 形式化验证，并画出对应的状态图。操作者看过代码、验证结果和图之后，说「合」才合并。没有操作者明说的部署请求，不部署。`docs/envisioned-product/` 里的文档不是实现许可，也不是合并许可。

PNG 和 PDF 仍是上传原件。模块⑤在那两份图上仍印着四种状态。可编辑的图源 `mermaid-rows/02-dispatch.mmd` 和 `mermaid-rows/03-gate.mmd` 已按这次细化改过。实现以计划和这份记录为准。

## 2026-11-12 操作者决定补上默认搜索

这一条只补 `ev-net`。它不改十四刀的顺序，也不把计划正文里的原句改写成早就这样写过。

操作者决定，不要地球按钮，也不要每轮先说「上网」才允许搜索。默认像个人助手一样具备搜索能力。用户说搜就可以搜。需要新信息时由模型自己决定。这是默认提供能力，不是每一句都强制搜索。

计划里「允许列表含「上网」才打开」被这一条替代。代码不读「上网」这个词。已经存在的硬开关仍是这一代 `allowed_tools` 里有没有 `web`。默认宪法名单含 `web`，所以普通一轮会附带搜索。名单里拿掉 `web`，这一轮就不附带，也不再走智谱搜索。用户在句子里说不联网，只写进回答提示，不是新的设置页。

官方 Responses 文档在 2026-11-12 写明，`POST /responses` 的 `tools` 里 `{"type": "web_search"}` 由 `deepseek-v4-pro` 执行，`deepseek-flash` 会忽略。省略 `tool_choice` 为自动选择。因此只有提供搜索的回答请求改用 `deepseek-v4-pro`。`chat_model` 仍是 `deepseek-flash`。聊天补全请求体不增加猜测字段。嵌入、重排、识图不动。

计划里的 live 行和其他刀的框保持未勾。这一条不部署，也不开始 `ev-events`。
